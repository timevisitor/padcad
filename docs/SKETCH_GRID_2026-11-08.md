# 草图网格：去掉「两层网格」并改为随缩放自适应（PadCAD 5.1.5）

日期：2026-11-08　版本：5.1.5（versionCode 68）　设备：小米平板 24091RPADC / HyperOS OS3.0（Android 16）/ WebView 143.0.7499.192

## 1. 问题

真机 5.1.4 进入草图后，背景出现**两层网格**：一层跟着平移/缩放在动，一层固定不动、钉死在屏幕上；
另外网格有硬边界——平移到远处或缩小后，网格在某一侧突然截断（headless 截图里左侧 x≈204 处可见）。

## 2. 根因

| 层 | 实现 | 行为 |
|---|---|---|
| 第一层 | `#view` 的 CSS `linear-gradient` 方格（28px，screen 坐标） | 不随相机动 → 看起来"钉死" |
| 第二层 | `drawSketchGrid()` 画在草图平面上的 three.js 线（世界坐标） | 随相机平移/缩放 |

两层同时可见，就是用户看到的错位叠影。网格的硬边界来自旧实现固定 `±60mm / 2mm 次格`（`N=30, small=2`），
视野一旦超出这个范围就没有线了。

## 3. 改法（`src/main.js` + `src/workspace-ui.css`）

1. 进草图时给 `body` 加 `sketch-grid-on`，`#view` 的 CSS 方格让位（只留径向渐变底色）；退出草图/切 3D 自动移除。
2. three.js 网格改为**随缩放自适应**：
   - 次格间距按 `mmPerPx` 选 1/2/5/10 × 10ⁿ 系列，屏幕上次格稳定在 14–35px；
   - 主格 = 次格 ×5（或 ×2），每 5 根一根主格；
   - 范围以视野中心为准、向外扩 1.6× 对角线，始终铺满屏幕，不再有硬边界；
   - 三种样式（坐标轴/主格/次格）各用一个 `LineSegments` 合批，替代原来每根线一个 draw call（旧实现 122 个对象）。
3. `gridSig()` 签名（缩放档 + 视野中心量化 + 画布尺寸）驱动按需重建，120ms 的 UI tick 里比较签名。
4. 顺手修：`drawSketchGrid()` 在范围保护提前 `return` 时未写签名，会让 tick 反复清空重建空网格；改为先写签名再判范围。

## 4. 客观证据（`<资料目录>`）

判据不靠肉眼：沿纯背景带做列灰度 → 去趋势得线深度 → 拟合主栅格 P（首尾跨度/周期数，浮点）→
算每条线的相位残差（折叠到 [0,P/2]）与内点相邻间距 std。
**PASS = 离群率 ≤6% 且内点间距 std ≤2.0px**（离群线允许图元边缘/坐标轴/控件混入，不会一条就翻盘）。

| 图 | 主栅格 P | 内点间距 std | 离群率 | 判定 |
|---|---|---|---|---|
| 改前 v5.1.4 · 进草图（headless） | 25.18px | 22.07px | 44.1% | **FAIL 双层** |
| 改后 5.1.5 · 进草图（headless） | 36.34px | 0.47px | 0.0% | PASS 单层 |
| 改后 5.1.5 · 平移+缩放后（headless） | 36.89px | 0.31px | 0.0% | PASS 单层 |
| 改后 5.1.5 · 缩小远移后（headless） | 36.34px | 0.31px | 0.0% | PASS 单层 |
| 真机 5.1.5 · 进草图 | 50.03px | 0.43px | 2.5% | PASS 单层 |
| 真机 5.1.5 · 正视草图平面 | 50.00px | 0.00px | 0.0% | PASS 单层 |
| 真机 5.1.5 · 退出草图（CSS 方格） | 77.14px | 0.99px | 0.0% | PASS 单层 |

改前那 58 条线里能清楚分出两族：一格 36px（three.js）、一格 56px（CSS 28px × dpr 2），两者互不整除 → 错位叠影。

真机上主格/次格可辨：次格 Δ≈6.4 灰阶 30 条、主格 Δ≈18.9 灰阶 6 条，间距正好 5.00×P（250px）。

## 7. 残余限制

- 真机**双指捏合缩放**未自动化（`adb input` 不支持多点触控）；缩放路径由 headless `Input.dispatchMouseEvent` 滚轮缩放覆盖，真机只验到单指/按钮路径。手感需人工确认。
- WebGL 下 `linewidth` 被实现固定为 1px，主格无法"加粗"，只能靠颜色/不透明度拉开层次（当前深度比约 2.5–3×）。
- 建模模式仍是原 CSS 屏幕方格（28px，不随相机动）——本轮只处理草图里的叠影，未改建模模式的观感。
